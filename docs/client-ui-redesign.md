## 2. 布局选型:不合并三区,改为垂直导航

### 2.1 决定

保留翻译 / 查词 / 状态三个功能区的硬区隔,但把承载它们的 `QTabWidget` 换成 **左侧固定宽度垂直导航栏(168px)+ `QStackedWidget`**。三个 view 的构造、信号、asyncio 任务字段一律不动,只换父容器与切换控件;结构改动集中在 `main_window.py` 约 40 行内。

区内顺序调整为 **术语查词(默认落地区)→ 文本翻译 → 服务状态**。owner 日常最高频的是查词,它应该是启动后光标已经在的那个输入框。

导航栏底部空出常驻位放 endpoint 状态芯片,把现在那行横贯整窗、浮在 tab 上方的 `QLabel` 收进一个有归属的容器,主内容区从窗口顶部就是内容。

窗口最小 960×640,默认 1100×720。菜单栏保留,不做自绘标题栏(避免拖拽、阴影、DPI 三类自绘风险)。

### 2.2 为什么不合并

三个候选方案经三镜头评审面板独立打分,结果 2:1:

| 方案 | 可用性 | 工程落地与门风险 | 契约验收覆盖 |
|---|---|---|---|
| 搜索优先单窗(合并) | **8** | 4.5 | 6 |
| **三区精修(不合并)** | 5.5 | **8** | **8.5** |
| 词典优先混合台(合并) | 7 | 6 | 7 |

支持不合并的实质理由,不是"改动小"这一条:

1. **三个功能区的使用节奏相差一到两个数量级。** 查词高频、短、几乎是反射动作;翻译低频、长、**且要花钱**;服务状态极低频,只在"怎么突然不好使了"时才看。合并成一个输入框等于假设三者节奏相同。
2. **成本结构不该被一个输入框抹平。** `client/README.md` 钉死了一句 "a dictionary hit never reaches the model and costs nothing",反过来说模型分支是花钱的。一个输入框既可能触发免费词典查询、也可能触发付费模型调用,这个歧义要靠键位约定(Enter vs Ctrl+Enter)来消解——而键位约定是隐性知识,花钱的动作不该依赖隐性知识。
3. **合并会击穿承载安全不变式的验收面。** 合并方案分别击穿约 15+ 与 10+ 条断言,且改的都是承载「拒绝可见」「零半应用」「换址清屏」这些不变式的测试。重写这些测试本身就是风险,而它们保护的是凭据与传输行为——契约明确要求零回归的那部分。
4. **首启流程页面化会动到 CI 唯一的构造排练路径。** `build.ps1` 的 `--self-check` 是打包产物唯一的自动验证,它完整构造 `MainWindow`。把 first-run 从模态对话框改成同窗页面,等于把这条排练路径置于重构之下。

### 2.3 可用性镜头的异议,及如何吸收

可用性评审判合并方案胜出,核心论据是**「查词未命中 → 需要翻译」这个真实判断时刻**:三区隔离下 owner 要切区、重新输入一遍。这个批评成立,因此本方案吸收以下嫁接(来自两个落选方案),不改骨架:

- **未命中桥。** 查词空结果态提供「用模型翻译「{query}」」按钮,携带查询串直达翻译区并预填,消掉重复输入。
- **键盘跳区。** `Ctrl+1/2/3` 切区,`Ctrl+K` 聚焦当前区输入框;否则"键盘流"不成立。
- **未配置态三步引导清单**(设置地址 / 录入令牌 / 开始查询,每步带完成态),覆盖"地址和令牌都缺"时先修哪个的真实困惑。判定只读 `base_url is None` 与 `has_token()`,零请求。
- **句子短路。** 查询串过长或含换行时判定为句子,不打词典接口,面板直接指向翻译区。

> 本节原先还列了「请求刹车(指数退避 + 自动查询暂停)」与「32 条查词 LRU 缓存」两项。
> 两者连同输入即搜整体**未实现**,见 §4.1。

## 3. 视觉系统:设计令牌

### 3.1 基调

克制的工具感,不是游戏皮肤。「一张干净的纸 + 一个功能色」:大面积中性灰白/深灰,单一青绿 accent 只出现在主按钮、当前导航项、焦点环三处;语义色只出现在徽章与 banner。无渐变、无阴影堆叠(卡片与 banner 用 1px 边框而非投影分层)、无装饰性插画。信息密度中等偏高——owner 是单人重度使用者,需要一屏看完「来源 / 可信度 / 请求 ID」。

全部视觉靠 QSS + 纯几何绘制,**零位图、零图标字体、零网络资源**。

亮暗两套色值一一对位、令牌名相同;亮/暗只是同一份 QSS 模板的两次取值,不允许某个语义色只在一套里有定义。

### 3.3 字体与字号

字体栈全部为 Windows 本地自带字体,不引入任何需下载的资源:

```
界面主栈  "Microsoft YaHei UI", "Microsoft YaHei", "Segoe UI", "SimSun", sans-serif
等宽栈    "Cascadia Mono", "Consolas", "Courier New", monospace
```

等宽栈仅用于请求 ID、data commit、term count 这类标识符与数字。西文字体放在中文字体之前可让西文用 Segoe UI 而中文回落雅黑,是 QSS 回退链的标准中英混排做法;此处主栈把雅黑 UI 放首位以保证中文界面的一致度量,西文由雅黑 UI 自带西文字形承担。

字号阶梯用 **pt**(随 Windows 文本缩放放大):

| 级别 | 字号 | 字重 | 用途 |
|---|---|---|---|
| display | 18pt | semibold | 仅首启标题 |
| title | 14pt | semibold | 对话框标题、区域主标题 |
| section | 12pt | medium | 卡片分组标题、结果小标题 |
| body | 10.5pt | regular | 正文、输入、结果、表格、按钮 |
| secondary | 9.5pt | regular | 说明文字、空状态副题、banner 正文 |
| caption | 9pt | regular | 请求 ID、字段错误、状态条、占位符 |

字重只用 regular(400)/ medium(500)/ semibold(600)。**不使用 bold(700)**——微软雅黑的伪粗在小字号下发糊。正文块行高 1.55,单行控件由 padding 决定。

### 3.4 间距与圆角

间距阶梯(px,Qt6 下随 devicePixelRatio 缩放):`2 / 4 / 8 / 12 / 16 / 24 / 32 / 48`。**只用这八个值**,不出现 6/10/14/20 这类中间值。

圆角阶梯(px):`0`(表格分隔)/ `4`(徽章内点)/ `6`(按钮、输入、下拉)/ `10`(卡片、banner、结果框)/ `14`(对话框内层卡)/ `999`(pill 徽章、endpoint 芯片)。

控件高度一律用 `min-height + padding` 表达,**不用定高**——150%/200% 缩放下定高会裁字。参考值:输入/按钮 32px,紧凑按钮 28px,徽章 22px,导航项 40px,表格行 32px,状态条 28px。

描边:常态 1px `border-subtle`;hover 1px `border-strong`;焦点 2px `accent`(用 border,Qt QSS 无 outline 渲染)。**焦点态 2px 会让控件视觉尺寸跳变,常态需预留 1px 补偿**(常态 border 1px 时 padding 多 1px,焦点 2px 时减 1px)。

## 4. 交互重设计规格

### 4.1 查词:提交驱动(输入即搜未实现)

**本节描述的输入即搜没有实现。** 它在 PR #63 的中间提交里存在过,合并前被整体撤掉,
查词回到与改版前相同的**提交驱动**行为:按「搜索」或回车才发请求,请求进行中按钮禁用,
在飞时不接受第二次提交。撤掉的机制是防抖定时器、generation 乱序守卫、按键作废在飞请求、
重复闸,以及此前已单独撤掉的请求刹车与 LRU 缓存。

撤掉的理由与重新实现前必须先解决的判定点,记在配套 issue,不在本文档展开。这里保留
原设计的记录,是因为下一次要做这件事时,下面这些**分析**仍然成立,而它们不容易重新推导出来:

> **输入法。** 中文输入法候选框阶段不改变 `QLineEdit.text()`(preedit 不进 text),所以
> `textChanged` 天然只在上屏后触发,不需要额外挂 `inputMethodEvent`。这是选用 `QLineEdit`
> 而非 `QPlainTextEdit` 的关键理由:它把一个"只能真机手测"的验收缺口变成架构上不存在的问题。
>
> **被吞掉的 `CancelledError`。** `ApiClient._request` 把 `asyncio.CancelledError` 消化成
> `ClientError('cancelled')`,所以 await 方拿到的是一次**正常返回**而不是取消。只调 `cancel()`
> 不做别的,旧请求的 `cancelled` 仍会回到 view 并覆盖新请求的加载态——取消替换语义因此需要一个
> 单调 generation,在协程的**每一个出口**比对后才允许写 UI。这一条即使不做输入即搜也要知道:
> 换址重置同样走 cancel,同样产生一个必须被丢弃的 `cancelled`。

### 4.1a 当前实际行为

**触发。** 「搜索」按钮与回车,二者等价。请求进行中按钮禁用;回车绕过禁用的按钮直达处理函数,
所以处理函数自身还有一道在飞守卫——否则每次回车都会再起一个任务并覆盖 `_task`,回复可能乱序落地。

**两道提交时闸。** ① strip 后为空 → 不发请求;② strip 后长度 > 40 或含换行 → 判定为句子,
不打 `GET /v1/terms`,面板显示专用文案并提供直达翻译区的按钮。两道都在提交那一刻判定,不需要定时器。

**加载态。** 状态条「搜索中…」+ 一条不确定进度线。**失败与换址清空表格**,不保留旧结果:
这两条是改版前就有的行为,现由 `test_view_parity_with_main.py` 断言。

**未配置。** 按钮禁用并挂 tooltip 指向设置;传输层的 `not_configured` 分支原样保留做兜底。

### 4.2 翻译来源可视标识

一枚 `QFrame#kindBadge`(pill,圆角 999,min-height 22,soft 底 + 1px 同色边),内含 `QLabel#kindDot`(8×8)+ 中文文本。**形状 + 色相 + 文字三重编码**,任一维度单独失效仍可分辨(色觉障碍、灰度截图下都可读):

| kind | 形状(纯 QSS 几何) | 色 | 文案 |
|---|---|---|---|
| `exact` | 实心圆(border-radius 4px) | success | 词典精确匹配 |
| `fuzzy` | 空心圆环(transparent + 2px border) | warn | 词典模糊匹配 |
| `llm` | 圆角方块(border-radius 2px) | info | 模型翻译 |
| `noop` | 横杠(10×2px) | muted | 无需翻译 |

服务端返回未知 kind 时退化为 noop 形状 + 原始字符串(保留现有 `_KIND_LABELS.get(result.kind, result.kind)` 兜底)。

**实现陷阱点名:** 样式切换用 `setProperty('kind', value)` + `style().unpolish(w)` / `polish(w)` 强制重算。**漏掉 unpolish/polish 是这套方案最容易踩的 Qt 坑**,所有动态 property 切换必须封装进控件方法内统一处理。

`dictionary_miss=true` 时在 kind 徽章右侧追加**第二枚独立徽章**(warn 环 +「未匹配官方术语」),并在译文框下补一行说明该结果不具权威性。它是附加维度,**永不替换** kind 徽章——现状把 kind、附注、请求 ID 三段用 ` | ` 拼成一行,读者要自己切分。

**请求 ID 独占一行**,位于结果块最下方:等宽 9pt、muted 色、中部省略、右侧「复制」按钮,完整值挂 tooltip。**失败态用同一控件、同一位置渲染**——"出事了拿什么去问"不因成败而换地方;`request_id` 为 `None` 时渲染占位符而非隐藏该行,避免 banner 高度跳变。

查词表格的 `reason` 列换成同一套点形词汇:`exact`→实心圆「精确」;`pinyin` 系列→warn 环 +(拼音全拼 / 拼音缩写 / 拼音前缀 / 拼音包含);`fuzzy`→info 环「模糊」;`low-score`→横杠「低相关」;未知值→横杠 + 原字符串。`score` 列保留数值并在其后画 40px 细条按 0–100 填充。**匹配方式不得只活在 tooltip 里。**

### 4.3 内联错误与加载态

只引入两种新呈现面,**不引入 toast**(浮层要自管生命周期、定位与堆叠;本方案每一类反馈都有确定归属区域)。

| 呈现面 | 形态 | 承接 |
|---|---|---|
| 区域 banner | 内容区标题下,圆角 10、soft 底、1px 同色边、左侧 4px 色条,≤2 行 + 右下动作按钮,可关闭 | 「这次请求失败了」 |
| 字段级错误 | 输入框描边转 danger + 其下一行 danger caption | 因在用户手上那一格里的错误 |
| 全局 banner | 主内容区最顶端、跨区常驻 | 未配置 / 不安全地址(不可关闭)、设置未能写盘(可关闭) |
| 状态条 | 单行 muted caption,由下一次动作覆盖 | cancelled、已复制、已保存——**确认类,绝不着红** |

错误码分派(建议落成**两张显式 dict 常量表**:码→级别、码→动作,放 ui 层,再配一条"15 个码每个都有归属、无遗漏"的表驱动测试,把分派完整性从 review 项变成机器门):

| 错误码 | 呈现面 | 语气 | 动作 |
|---|---|---|---|
| `offline` `timeout` `internal` `unknown` `llm_unavailable` `llm_budget_exhausted` | 区域 banner | danger | 重试 |
| `rate_limited` | 区域 banner | warn | 重试(手动;自动退避未实现) |
| `unauthorized` `forbidden` | 区域 banner | warn | **输入新令牌**(直开 TokenDialog,比"打开设置"少一跳) |
| `not_configured` `insecure_endpoint` | 全局 banner | warn | 打开设置 |
| `invalid_request` `input_too_long` `payload_too_large` | 字段级 | danger | 无(焦点回字段) |
| `cancelled` | 状态条 | muted | 无 |

**占位纪律:** 主 banner 同一时刻至多一条(新替换旧);同一次操作若词典与翻译都失败,主位置只报翻译、词典在自己分区内报——**一次操作绝不出现两条红**。加载态一律是「顶部 2px 不确定进度条 + 状态条文案」,永不是模态、永不是遮罩。

### 4.4 现有阻断弹窗的逐个去向

| 现状位置 | 现状 | 改为 |
|---|---|---|
| `settings_dialog._on_accepted` 地址非法 | `QMessageBox.warning` | 对话框内地址字段的字段级错误位,对话框保持打开、焦点回字段 |
| `main_window._apply_settings` 中 `update_base_url` 抛错 | `QMessageBox.warning` | 同一字段级错误位(需给 `SettingsDialog` 加 `show_base_url_error(text)` 公开入口) |
| `_apply_settings` 设置未能写盘 | `QMessageBox.warning` | 主窗口全局 warn banner(它发生在对话框已关闭后,是会话级跨区事实) |
| 凭据存储不可用 / 遗忘失败(3 处) | `QMessageBox.critical` | 就近 inline danger banner:设置里在「设备凭据」卡内,首启在对话框内 |

**全应用保留的模态只剩两个:** 遗忘令牌的 `QMessageBox.question`(破坏性、不可撤销、需要一次真决策,内联化会削弱它),以及「关于」的 `QMessageBox.information`(非错误、非流程阻断)。这两处保留请 owner 在审阅时确认符合"不弹阻断式对话框"的本意。

### 4.5 未配置态、首启与令牌录入

**未配置态三处同时表态且措辞不重复:** 导航底部芯片(danger 圆点 +「未配置」)说"是什么状态";顶部不可关闭全局 banner 说"后果是什么"(不会发出任何请求)+ 唯一动作;当前区空状态卡说"去哪儿改"+ 三步引导清单。

UI 层短路提交:翻译/搜索/刷新按钮 disabled 并挂 tooltip 指向设置,防抖计时器不启动。**传输层的 `not_configured` 分支原样保留做兜底——UI 短路是降噪,不是安全边界。**

**芯片文案诚实性:** 已配置地址只显示「已配置」,**不显示「已连接」**——客户端在首次成功请求前从未验证过连通性,写"已连接"是谎言。首次请求成功后方可升级文案。

**首启与令牌录入行为改动三处:** ① 空令牌时「继续」disabled(现状是可点但静默 setFocus,读起来像按钮坏了);② 令牌字段右贴「显示」切换按钮(`EchoMode` Password↔Normal),粘贴后可核对首尾;③ 凭据存储失败不再 `QMessageBox.critical` + 关闭应用,改为对话框内 danger banner,对话框保持打开可重试。

**「无凭据不得进入主窗口」这条安全约束仍由 `ensure_credential` 的返回值保证**:只有用户主动按「退出」(reject)才返回 `False`,凭据写入失败的路径返回到对话框循环而不是返回 `True`。保留原生标题栏与 `QDialog`,不做 frameless,首启时序完全不动。

### 4.6 换址重置与取消按钮

**换址反馈:** 现状是三区静默清空,看起来像"东西丢了"。改为:info 语气可关闭全局 banner(服务器地址已更改,上一台服务器的结果已清除)+ 导航芯片一次 240ms 高亮 + 三区各回空状态卡,文案是「已切换到新的服务器地址,重新发起请求以获取结果」而非首次启动那句。

**取消语义完全不变:** 仍是 fire-and-forget,不 await、不 gather、不 wait_for。视觉反馈只加在"已经清掉了什么"上,**绝不暗示"已经停掉了对方的工作"**。

**取消按钮只有翻译区有**(查词已是自动替换,再放取消按钮是多余的决策点)。紧贴「翻译」右侧**常驻占位**——idle 时 disabled 而非隐藏,避免运行态出现时整行横向跳动。状态机:idle = [翻译可点][取消 disabled];running = [翻译 disabled][取消可点] + 进度条;点击取消后 = 两个都 disabled + 「正在取消…」,直到 done_callback 落地写终态。

**终态文案必须与 README 钉死的英文语义一致:** 写「已取消等待」这一类表述,并补一行说明服务端可能仍在处理、已产生的开销不会退回——**绝不写成"已立即中止请求"**。中文化时逐条对照 README 那五句英文断言,不得引入与之矛盾的中文承诺。

## 5. 中文化方案

`strings.py` 全量中文化,**只改值、不改常量名、不改结构**:

- 保持平铺 `NAME = "中文"` 形式。**禁止**重构为 dict / 嵌套类 / gettext——静态门按 AST 计数模块级字符串常量(需 ≥20)。
- 保留 `.format` 占位符 `{base_url}` 与 `{request_id}`,否则直接 `KeyError` 或丢信息。
- 15 个错误码逐条中文映射齐全、**两两互异**(`not_configured` / `unknown` / `insecure_endpoint` 被断言互不相等)。
- 未配置文案里**不举开发地址为例**(现有断言:未配置态文案不含 `127.0.0.1`)。
- `APP_TITLE` 可中文化——已核实它只被 `setApplicationName` 与 `setWindowTitle` 使用;keyring 服务名与配置目录名是各自独立的硬编码字面量,不从它派生。

**`client/README.md` 不能全量中文化。** 采用「中文正文 + 原样保留英文钉死块」结构:仓库级门钉死了 5 句英文取消语义句与 1 句 operations note,翻译其中任何一个字都会让仓库套件变红。中文段落还需避开若干英文词(见 §7.1)。

### 7.2 待裁决 B:暗色偏好持久化

契约要求"含暗色模式"。技术事实(已核实官方文档):`QStyleHints.colorScheme` 自 Qt 6.5 可用,可读系统主题并监听 `colorSchemeChanged`;但 `setColorScheme`(应用内强制)**要 Qt 6.8+**,而 `pyproject.toml` 允许 `PySide6>=6.7,<7`。所以应用内切换只能靠切换自家 QSS,不能靠 Qt API。

问题在持久化:`config.json` 的键集合被 `test_config.py:35` 与 `test_config_persistence.py:85-89` 钉死为恰好三键。写入主题键必然让这两个测试变红。

**两个选项:**

| | 方案一:仅跟随系统 | 方案二(建议):跟随系统 + 手动三态 |
|---|---|---|
| 契约满足度 | 有暗色但 owner 无法固定 | 完整 |
| 门冲击 | 零 | 需同步改 2 处断言(均在 `client/` 边界内) |
| 风险 | 无 | 改的是"配置文件不含凭据"这条安全断言所在的文件——必须保留禁 token 断言与原子写语义 |

**建议方案二**,理由:两个测试都在 `client/tests/` 边界内可改;扩展键集合是显式、可审计的一行改动;而"跟随系统"在 owner 想固定暗色时无解。若 owner 认为不值得动那两处断言,方案一是安全退路,设计其余部分不受影响。

### 7.3 待裁决 C:文档落位

本文与 ADR 落在 `docs/`,不在 `client/`。边界写的是"仅动 `client/`",但该边界与"服务端与 API 契约零改动"并列,读起来是**针对产品代码**;而 ADR 按仓库惯例住 `docs/adr/`(现有 ADR 0011 正是记录本客户端的),且 ADR 本身是契约列明的交付物。请 owner 确认这一读法。若要求严格,可改放 `client/docs/`——但那样会落入 transport 严格面,文档里出现若干英文词就会挂 CI。

**「拒绝可见」「零半应用」「换址清屏」「防乱序」四条不变式一条都不许弱化**——这是替换保护,不是删除保护。缺一条承接说明即视为用改测试掩盖回归。

### 7.5 新增的机器门(把已知盲区变成 CI 红灯)

改版顺带补两道现在没有的检查:

1. **资源链条锁死。** pytest 阶段一条「spec datas 覆盖 `resources/` 全部文件」的测试(读 spec 文本与目录清单比对),拦"加了新资源忘进 datas";构建阶段一条 `dist` 下 `.qss` 存在性断言,拦"datas 路径写错"。两道都有才封住"打包产物静默无样式"——`--self-check` 不检样式,这是它的盲区。
2. **错误分派完整性。** 码→级别、码→动作两张 dict 表 + 表驱动测试,断言 15 个码每个都有归属、无遗漏。

**中文化完整性无法完全机器化:** 既有"ui/ 无内联文本"静态门证明的是"文案都来自 strings.py",不是"strings.py 里没有英文残留"。可补一条弱检查(扫 `strings.py` 的值,除白名单标识符外不得含连续拉丁字母单词),但白名单本身需人工维护——请 owner 知悉这一项的证明强度上限。

## 附:本方案的证据来源

设计由 9 个并行代理产出并经三镜头评审面板裁决:约束审计(9 条硬约束 / 15 组测试依赖 / 10 处中文化爆点,逐条引用文件:行号)、交互流程盘点(10 条流程 / 46 行状态矩阵 / 7 条契约差距)、Qt 技术核查(14 条事实,均带官方文档来源或本仓库文件行号)、三份差异化设计提案、三份评审裁决。

其中四条承重结论由主控回路**独立复读源码复核**:英文「别名」一词的全词禁用规则、`config.json` 三键钉死、`WuwaTerm.spec` 的 `datas=[]` 现状、`tabs.count()==3` 与「在跑即忽略」守卫。两名评审代理运行时安全分类器不可用,其结论仅在与上述实读证据一致处采信。

**本文档自身也过了这些门**:撰写时首版在说明表格里原样写出了两个被禁的英文词,当场被 `check_non_goals.py` 拦下——这恰好证明了 §7.1 那两行的真实性,也是新增中文文档必须做提交前自查的实例。
